## 1. 背景与现状

**事实（来源：本仓库 README.md/ CLAUDE.md/ 目录实况）**



* my-wiki 是基于 Karpathy LLM Wiki 方法论的个人知识库：`raw/` 存**不可变原始资料**（md /html/pdf，附件在 `raw/assets/`），`wiki/` 是 LLM 派生的理解层（`summaries/` `entities/` `concepts/` `comparisons/` `overviews/` `synthesis/` + `_index.md` + `_log.md`）。

* 当前规模：wiki 层 14 个 md，raw 层 2 md + 1 html + 1 pdf；全部文件以 Markdown + `[[wiki-link]]` 组织，页面带 YAML frontmatter（type/title/sources/created/updated/tags/aliases）。

* 硬规则（CLAUDE.md）：`raw/`**&#x20;一旦存入，永远不修改、不删除，只追加**；`wiki/` 可重生；纯 Markdown；操作留痕（更新 `_index.md` / `_log.md`）。

* 现有浏览方式：Obsidian（推荐）、VS Code、任意 md 编辑器、命令行 grep。

**要解决的问题**



1. 不开 Obsidian、不敲命令行，用浏览器就能读 wiki 笔记和 raw 原始资料（md/html/pdf）。

2. **看到值得收藏的文档时，需要一个 "先放进来、稍后再让 Agent 整理" 的落点**—— 当前没有这样的位置，只能直接丢进不可变的 `raw/`（不合规）或散落在系统其他目录（会丢）。

3. 按类型（原始 / 摘要 / 实体…）快速切换查看，而不是只能在长文件树里翻。

4. 读摘要时点 `[[实体]]` 想顺手看一眼，但不想丢掉当前阅读位置。

## 2. 目标与非目标

**目标**



1. 浏览器查看：索引首页、分类 Tab、文件树、wiki 笔记阅读、raw 原始资料阅读（md /html/pdf）。

2. **暂存区**：收藏落盘、暂存清单管理、标记待整理、Agent 整理后归档。

3. 查找：文件名 + 正文全文搜索。

4. 轻管理：受项目规则约束的文件操作。

5. 阅读体验：分类 Tab 快速查看 + 侧栏预览不打断阅读 + 全中文界面。

6. **网址收藏**：输入公开 HTTP/HTTPS 地址，将该地址返回的原始文件保存到暂存区，等待后续 Agent 整理。

**非目标（本期不做）**：复杂页面排版器（自由布局、文本框、分页）、多人协作、远程 / 云部署、移动端 App、关系图谱、git 操作、向量 / RAG 检索、Web 端调用 LLM 自动整理（整理仍由你在 LLM CLI 中触发）、Typora 的像素级复刻或专有能力复刻。

## 3. 核心产品判断与取舍

### D1 形态：本地轻服务（直读文件系统），而非静态站点生成



* **理由**：wiki 持续被 LLM agent 更新，直读文件系统保证每次打开即最新状态；管理与暂存操作需要实时写文件。

* **取舍**：比纯静态多一步 "启动服务"，用一条命令解决（启动后自动打开浏览器）。

* **调整条件**：若未来需要公网访问或多人，再引入构建层 / 部署，本期不做。

### D2 三区权限模型（关键取舍）

引入 `inbox/` 后，知识库变成三区结构，各区权限不同：



| 目录                | 性质                            | Web 端权限                     | 理由                       |
| ----------------- | ----------------------------- | --------------------------- | ------------------------ |
| `inbox/` **（新增）** | **暂存区**：未经 Agent 整理，可变、可删、可改名 | **完全可写**：收藏、编辑、重命名、删除、标记状态  | 这是 "草稿箱"，本就应该随手整理，无不可变约束 |
| `raw/`            | 不可变，只追加                       | **严格只读**：不提供编辑、删除、重命名       | 违反 "不可变" 会破坏知识库可信度       |
| `wiki/`           | 可重生，agent 维护                  | 轻管理：新建 / 重命名 / 移动 / 编辑 / 删除 | 网页可直接整理，与 agent 流程不冲突    |

**为什么单独建&#x20;**`inbox/`**&#x20;而不是直接写进&#x20;**`raw/`：`raw/` 的不可变性是这套知识库可信度的根基 —— 一旦允许 "先随便丢进去再改"，raw 就不再是可靠的原始快照。暂存区把 "随手收藏（可反复修改）" 和 "正式原始资料（永不变更）" 在物理上分开，收藏动作因此变得零心理负担。

### D3 暂存区的流转与责任边界（核心新增判断）



```
收藏 → inbox/（待整理）→ 你在 LLM CLI 说"整理 inbox" → Agent 生成 raw/ + wiki/ 派生层 → inbox 文件标记已归档
```



* **Web 端只负责 "存" 和 "标记"，不负责 "整理"**：整理（生成摘要 / 实体 / 索引）仍由 LLM Agent 完成，Web 端不内置 LLM 调用。这是本期明确的责任划分，避免 Web 端与 Agent 双写冲突。

* **Web 端提供的抓手**：一键复制 "整理 inbox/xxx" 指令到剪贴板，方便你粘到 LLM CLI 里；首页显示待整理数量提醒。

* **归档不删除原件（暂定）**：Agent 整理后，inbox 文件默认保留并标记 `status: archived`，由你手动清理。理由：整理质量需要你确认后再删，自动删除不可逆。若你希望自动清理，改为 F21 可选开关。

* **状态记录方式**：暂存文件为 md 时写入 frontmatter `status`（`inbox` / `archived`）；非 md 文件（pdf/html/ 图片）无法写 frontmatter，状态记录在 `inbox/_inbox.md` 清单中（本文件由 Web 端维护）。

### D4 分类 Tab（新增判断）



* 阅读区顶部提供固定 Tab：**原始 / 摘要 / 实体 / 概念 / 对比 / 综述 / 归档 / 暂存**，对应 `raw/`、`wiki/summaries/` 等目录及 frontmatter `type` 字段。

* 每个 Tab 内是该类型页面清单（标题 + 更新日期 + 标签），点击进入阅读。Tab 上显示条目数（如「实体 9」），空分类显示为置灰并提示 "暂无（需 2 篇以上资料提及后建立）"，与项目建页规则一致。

* **归类依据优先 frontmatter&#x20;**`type`**，目录路径作为兜底**—— 因为 type 是项目规范里的权威字段；两者冲突时以 frontmatter 为准并在元信息面板提示。

### D5 侧栏预览（新增判断）



* 点击 md 正文中的 `[[wiki-link]]`：**在右侧预览栏打开目标页面，主阅读区保持不动**（含滚动位置）。

* 预览栏内可继续点链接（栏内替换，并提供「返回上一篇」），也可「在主区打开」升为主视图，或关闭。

* 预览栏支持拖拽调宽、记住宽度；窄屏（<1024px）降级为底部抽屉或全屏浮层，避免挤压正文。

* **文件树 / 搜索结果 / Tab 清单的点击仍在主区打开**（那是明确的导航意图）；只有正文内联链接走侧栏预览（那是顺手查看意图）。

### D6 全中文界面



* 所有导航、Tab、按钮、状态、空态、错误提示、确认弹窗均为简体中文；技术术语保留必要英文（如 PDF、Markdown、HTML、frontmatter）。

* 文件名与文件内容原样展示，不做翻译。

### D7 安全底线



* HTML 文件（含 `inbox/` 中收藏的网页）用 **sandbox iframe** 渲染（禁脚本），防止携带恶意脚本。

* 所有文件读取接口做**路径规范化校验**，拒绝越出项目根目录。

* 服务默认绑定 `127.0.0.1`；写操作接口带简单令牌。

* 上传文件校验扩展名白名单（md/txt/html/pdf/png/jpg/jpeg/gif/webp），并限制单文件大小（暂定 50MB，可调）。

### D8 通过 URL 收藏原始文件

- **入口**：暂存区页面提供「从网址收藏」输入框；粘贴一个 `http://` 或 `https://` URL，点击「保存到暂存区」。前端只提交 URL，下载由本地服务端完成，避免浏览器跨域限制。
- **“原始文件”的定义**：保存服务器最终响应体的**原始字节**，不抽取正文、不转 Markdown、不重写 HTML、不执行 JavaScript、不调用 LLM。对于普通网页，保存收到的 HTML 响应；对于 PDF、图片、纯文本等，保存对应二进制/文本响应。
- **存储位置**：统一保存到 `inbox/files/`；元数据写入 `inbox/_inbox.md`，状态为 `inbox`。原始文件不直接进入 `raw/`，也不触碰 `wiki/`。
- **文件命名优先级**：①响应头 `Content-Disposition` 中合法文件名；②最终 URL 路径末段；③HTML `<title>`（仅用于命名，不改正文）；④域名 + 抓取时间。文件名清理路径分隔符、控制字符和系统保留字符；若缺少可靠扩展名，依据已验证的 `Content-Type` 补扩展名。重名追加 `-2`、`-3`，不覆盖已有文件。
- **重定向**：允许有限次数 HTTP 重定向（初始参数建议最多 5 次）；每一跳都重新做地址安全校验。清单同时记录用户输入的 `source_url` 与最终响应的 `final_url`。
- **元数据**：记录文件相对路径、source URL、final URL、抓取时间、HTTP 状态、Content-Type、文件大小、SHA-256、状态。凭证、Cookie、授权头不记录。
- **重复内容**：落盘前计算 SHA-256；若暂存区已存在相同内容，默认不重复写入，提示已存在文件并允许打开；同 URL 内容变化则保存新副本，不覆盖旧版本。
- **文件边界**：允许保存受支持的文档/网页/图片类型（HTML、Markdown、纯文本、PDF、常见图片）；响应类型不允许、超过大小上限、内容长度未知且流式读取超限时立即中止并删除临时文件。初始上限沿用 50MB，可配置。
- **失败真实性**：HTTP 4xx/5xx、登录页、验证码、反爬页面、空响应或下载中断，不得标记为成功的原始文档。能明确识别时提示原因；无法判断是否为目标内容时保存为「需确认」而不是「待整理」。
- **安全边界（SSRF）**：只接受 HTTP/HTTPS；拒绝 localhost、环回、私网、链路本地、组播、保留地址、云元数据地址及解析后指向这些地址的域名；禁止 `file:`、`data:`、`ftp:` 等协议；DNS 解析结果和实际连接目标必须一致，重定向后重复校验。下载不携带本机浏览器 Cookie、系统凭证或用户自定义请求头。
- **暂不支持**：必须登录后下载、依赖页面 JavaScript 才生成的文件、需要验证码或付费授权的内容。本期不自动操控浏览器绕过这些限制；用户可合法下载后通过文件上传入口放入暂存区。

### D9 Markdown 阅读与编辑：参考 Typora 的单栏即时渲染体验



* **产品定义**：不是 “源码编辑器 + 右侧预览” 的双栏模式，而是在同一内容区直接编辑渲染后的标题、段落、列表、表格、引用、代码块、图片和链接；光标进入当前块时，只在必要范围显示 Markdown 标记，离开后恢复渲染效果。

* **唯一真源**：磁盘中的 `.md` 原文始终是唯一真源；编辑器内部文档模型必须可无损序列化回 Markdown。不能保存 HTML、私有 JSON 或编辑器专有标记，不能擅自重排 frontmatter、列表缩进、代码围栏或 wiki-link。

* **两种模式**：默认「即时渲染」；工具栏可切到「源码模式」直接编辑完整 Markdown（含 frontmatter），切换前后内容与光标附近位置尽量保持一致。阅读只读文件时不展示模式切换。

* **编辑权限**：`wiki/**/*.md` 与 `inbox/**/*.md` 可编辑；`raw/**/*.md` 始终只读。只读页仍使用与编辑态一致的排版主题，避免显示效果割裂。

* **P0 格式能力**：标题 H1–H6、正文、粗体、斜体、删除线、行内代码、代码块（语言标识）、有序 / 无序 / 任务列表、引用、分隔线、链接、图片、表格、YAML frontmatter、`[[wiki-link]]` 与 `[[目标|显示名]]`。

* **交互**：选中文字后出现轻量浮动工具条；空行输入 `/` 打开中文命令菜单；支持常用 Markdown 输入规则与快捷键（如 `# `、`- `、`> `、`[] `、Cmd/Ctrl+B、I、K、S）。工具栏保持克制，不常驻占用正文宽度。

* **图片**：粘贴或拖入图片时，根据当前文档所属区写入对应附件目录 ——`wiki/` 页面写 `wiki/assets/`，`inbox/` 页面写 `inbox/files/`；正文插入相对路径。若附件写入失败，不插入失效链接。

* **保存**：输入停止后自动保存（初始防抖参数建议 800ms，可根据实际体验调整），同时提供 Cmd/Ctrl+S 立即保存；页面顶部显示「保存中 / 已保存 / 保存失败 / 外部已修改」状态。离开存在未保存内容的页面前必须提示。

* **并发冲突**：打开文件时记录内容版本（mtime + 内容摘要）；保存时若磁盘版本已变化，不直接覆盖，弹出「外部已修改」对话框，提供「查看差异」「保留我的版本」「加载磁盘版本」「另存副本」。默认不覆盖。

* **崩溃恢复**：未成功落盘的编辑内容暂存浏览器本地；再次打开该文件时提示恢复草稿。保存成功后删除对应草稿。

* **链接行为**：浏览态点 wiki-link 仍按 F23 在侧栏预览；编辑态中单击用于定位 / 编辑文字，按住 Cmd/Ctrl 点击才打开侧栏预览，避免误跳转。

* **参考边界**：“参考 Typora” 指参考其单栏、低干扰、即时渲染的写作体验；不承诺与 Typora 使用同一编辑内核、快捷键全集、主题系统或所有扩展语法。

### D10 其他阅读器与搜索



* **PDF**：优先浏览器原生 `<embed>`；跨浏览器一致性问题在 P2 换 PDF.js。

* **HTML**：sandbox iframe（不 `allow-scripts`、不 `allow-same-origin`）。

* **搜索**：P0 内存扫描文件名 + md 正文（含 `inbox/`）；文件量超～1000 或体验不佳时升级 SQLite FTS5（P1，条件触发）。

### D11 wiki-link 与 frontmatter 是一等公民



* 启动 / 文件变更时扫描 `wiki/`，构建「页面名 → 路径」映射（含 `aliases`），解析 `[[目标]]` 与 `[[目标|显示名]]`；无法解析标记为**断链**。

* 笔记页展示 frontmatter 元信息面板（type /sources/created/updated/tags/status）。

## 4. 目标目录结构（新增 inbox/）



```
my-wiki/

├── inbox/                 # 暂存区（新增·完全可写）

│   ├── \\\_inbox.md          # 暂存清单：非 md 文件的状态与来源记录

│   ├── 2026-09-06-某文章.md

│   └── files/             # 收藏的 pdf / html / 图片等原件

├── raw/                   # 不可变原始资料（只读）

│   └── assets/

├── wiki/                  # LLM 派生理解层（轻管理）

│   ├── summaries/ entities/ concepts/ comparisons/ overviews/ synthesis/

│   ├── \\\_index.md

│   └── \\\_log.md

└── docs/web-viewer-prd.md # 本文件
```



* `inbox/` 需纳入 git（属于知识资产，不写进 .gitignore）。**注意**：当前 `.gitignore` 已忽略 `.agents/` `.skills/`，与 inbox 无冲突。

* `inbox/files/` 存放非 md 原件，与 `raw/assets/` 命名习惯保持一致的思路（原件单独放子目录）。

## 5. 用户场景



| 编号  | 场景                | 路径                                                               |
| --- | ----------------- | ---------------------------------------------------------------- |
| S1  | 浏览知识库全貌           | 首页（统计 / 最近更新 / 待整理提醒 / 标签云）→ Tab → 笔记页                           |
| S2  | 按类型快速查看           | 顶部 Tab 切「实体」→ 9 条清单 → 点击阅读                                       |
| S3  | 阅读 wiki 笔记        | 笔记页（元信息面板、表格、代码块、图片、wiki-link）                                   |
| S4  | 读摘要时顺手查实体         | 摘要正文点 `[[Fireworks AI]]` → **右侧预览栏打开，主区不动** → 关闭继续读              |
| S5  | 阅读原始资料            | Tab「原始」或文件树 → md /html/pdf 在线阅读                                  |
| S6  | **收藏文档到暂存区**      | 拖拽 / 上传文件或粘贴 URL + 正文 → 落盘 `inbox/` → 标记「待整理」                    |

## 8. 非功能与安全



* **安全**：路径规范化校验；HTML 一律沙箱渲染；服务绑定 127.0.0.1；写接口令牌；上传白名单 + 大小上限（暂定 50MB，可调）。

* **性能（建议门槛，可调）**：百级文件文件树 <200ms；搜索 <1s；侧栏预览打开 <300ms。

* **一致性与防丢失**：写操作单写锁；Markdown 保存使用 mtime + 内容摘要做乐观并发控制；失败内容保留本地草稿；外部修改默认不覆盖。

* **编辑器性能（建议门槛，可调）**：常规笔记（约 1 万字）连续输入无明显卡顿；输入后渲染反馈目标 <100ms；自动保存状态可见但不打断输入。

* **数据**：文件系统即数据源，不引入业务数据库（P1 搜索索引除外）。

## 9. 技术方案要点（建议，可替换）



* **后端**：Python FastAPI 或 Node Express 二选一；`/api/tree` `/api/file` `/api/search` `/api/meta` `/api/tabs` + `/api/inbox/*`（上传 / URL 抓取 / 进度 / 取消 / 清单 / 状态）+ 受限写接口。

* **URL 下载器**：服务端流式下载到 `inbox/files/.download-*.part`，边下载边计数并计算 SHA-256；校验成功后原子重命名为最终文件。使用独立 HTTP 客户端，不继承浏览器 Cookie、代理凭证或环境授权头；DNS、连接 IP 与每次重定向均执行 SSRF 校验；设置连接/响应总超时和最大重定向数。

* **前端**：单页三栏 + 顶部 Tab + 右侧可开合预览栏；建议采用成熟的结构化编辑内核（优先评估 Milkdown/ProseMirror 或 Tiptap/ProseMirror），通过 Markdown 解析 / 序列化层保证原文可逆；不自行用 `contenteditable` 拼接富文本编辑器。

* **Markdown 安全与兼容**：阅读输出经过 DOMPurify；编辑器的 Markdown AST / 文档模型必须支持 frontmatter、GFM 表格 / 任务列表及自定义 wiki-link 节点；上线前用本仓库全部 md 做 “读取→序列化→文本差异” 回归，任何未编辑块不得发生语义或格式漂移。

* **上传**：multipart/form-data；拖拽用 HTML5 Drag & Drop。

* **搜索**：P0 内存扫描；P1 SQLite FTS5。

23. **在源码模式编辑 YAML frontmatter 与&#x20;**`[[目标|显示名]]`**，切回即时渲染模式后元信息与链接正确；再次切回源码时文本未被改写。**

24. **选中文字可使用工具条加粗 / 链接；输入&#x20;**`# `**、**`- `**、**`> `**、任务列表标记与&#x20;**`/`**&#x20;命令可创建对应块；Cmd/Ctrl+B、I、K、S 生效。**

25. **在 wiki 页粘贴图片，文件写入&#x20;**`wiki/assets/`**&#x20;且正文插入相对路径；在 inbox 页写入&#x20;**`inbox/files/`**；模拟附件写入失败时正文无失效链接。**

26. **输入停止后出现「保存中」并转为「已保存」；模拟后端保存失败时显示「保存失败」，内容仍在编辑器与本地草稿中，刷新页面可恢复。**

27. **编辑期间由外部进程修改同一文件，下一次保存不得直接覆盖；界面显示差异并提供保留我的版本、加载磁盘版本、另存副本、取消，默认不覆盖。**

28. `raw/`**&#x20;中的 md 页面与 wiki 使用同一排版主题，但看不到编辑按钮、快捷键不能写入，直接调用写接口也被拒绝。**

29. **浏览态单击 wiki-link 在右栏预览；编辑态普通单击只定位文字，Cmd/Ctrl + 单击才在右栏预览，主区编辑内容与光标不丢失。**

30. **输入一个公开的 PDF 直链后，下载文件位于 `inbox/files/`；其 SHA-256 与直接获取该 URL 最终响应体所得摘要一致，证明未做内容转换；`_inbox.md` 记录 source/final URL、抓取时间、状态码、Content-Type、大小与摘要。**

31. **输入普通 HTML 网页 URL 后保存收到的 HTML 原始响应，不转成 Markdown、不执行页面脚本；通过 HTML 阅读器打开时仍受 sandbox 限制。**

32. **URL 经 302 跳转到文件地址时，保存最终响应并同时记录原始 URL 与最终 URL；超过最大跳转次数不落盘。**

33. **输入 localhost、127.0.0.1、`::1`、私网地址、链路本地地址、云元数据地址，或解析后/重定向后指向这些地址的域名，请求均被拒绝且不产生暂存文件。**

34. **下载超过 50MB 的响应、4xx/5xx、空响应、超时或用户取消时，不产生最终文件；`.part` 临时文件被清理。**

35. **同一内容通过相同或不同 URL 再次收藏时，SHA-256 去重提示已有暂存项；同 URL 返回内容变化时保存新副本，不覆盖旧文件。**

36. **需要登录、验证码或被识别为反爬页面时，不显示“收藏成功”；可识别时提示失败原因，无法确定内容有效性时状态为「需确认」。**

## 11. 本期范围与暂不做

**本期做**：P0（F1–F10、F18–F33）+ P1（F11–F17）。

**暂不做**：P2 全部；多人 / 远程 / 云部署；向量 RAG 检索；**Web 端调用 LLM 自动整理暂存区**（整理仍由你在 LLM CLI 触发）；对 `raw/` 的任何修改 / 删除能力。

## 12. 风险与对策



| 风险                      | 对策                                                              |
| ----------------------- | --------------------------------------------------------------- |
| 暂存区变成垃圾堆，只进不出           | 首页常驻「待整理 N 篇」提醒；清单按收藏时间排序，久未整理项置顶显示                             |
| 收藏时误写 raw/ 破坏不可变规则      | 收藏接口只允许写 `inbox/`；raw 写入仅 F15 显式复制且纯追加；验收项 13 用 `git status` 核对 |
| 暂存区与 Agent 双写冲突         | Web 端不做自动整理；整理期间提示避免同时编辑同一文件；写操作单写锁                             |
| 收藏的 HTML 携带恶意脚本         | sandbox iframe 渲染，不 allow-scripts                               |
| 上传大文件 / 异常类型            | 扩展名白名单 + 大小上限 + 明确报错                                            |
| 侧栏预览层层嵌套迷路              | 栏内保留「返回上一篇」路径栈；预览栏只保留单层视图                                       |
| 重命名致断链                  | 全库引用同步 + 断链标识                                                   |
| Tab 归类与 frontmatter 不一致 | type 优先、目录兜底，冲突时在元信息面板提示                                        |
| 所见即所得序列化改写原文            | Markdown 原文为唯一真源；全库做读取→序列化差异回归；不支持语法降级为源码块，不静默丢失                |
| Web 与 Agent 同时修改导致覆盖    | mtime + 内容摘要乐观锁；保存前冲突检测；默认不覆盖并提供差异与另存副本                         |
| 浏览器崩溃或网络失败导致编辑丢失        | 本地草稿持续保存；重开文件时提示恢复；成功落盘后才清理草稿                                   |
| 图片写入失败但正文已插入链接          | 附件先落盘成功，再以原子操作插入 Markdown；失败不修改正文                               |
| URL 抓取被用于访问本机或内网服务       | 仅允许 HTTP/HTTPS；解析、连接和重定向逐跳执行 SSRF 校验，拒绝私网 / 环回 / 保留地址及云元数据地址 |
| URL 返回超大或无限响应耗尽磁盘         | 流式计数，达到大小上限立即中止；临时文件与最终文件分离，失败清理 `.part`                     |
| 把登录页 / 验证码页误当原始文件        | 检查状态码、Content-Type 与常见拦截特征；明确失败不报成功，不确定内容标记「需确认」              |
| 重复收藏浪费空间或覆盖历史版本          | SHA-256 内容去重；相同内容复用既有项，内容变化保存新副本，永不覆盖                         |
| 本地服务被同机进程访问             | 默认 127.0.0.1 绑定 + 写接口令牌                                         |

## 13. 待确认问题（不确认时按暂定方案推进）



1. **归档后是否自动删除暂存原件？** → 暂定：不自动删，标记「已归档」由你手动清理（整理质量需你确认，自动删除不可逆）。

2. **暂存区目录名用&#x20;**`inbox/`**？** → 暂定 `inbox/`（语义清晰、社区习惯）；也可改 `staging/` 或 `收藏/`。

3. **是否需要 Web 端把暂存项复制进&#x20;**`raw/`**（F15）？** → 暂定提供；若你希望 `raw/` 完全由 Agent 写入以保持单一写入源，可砍掉。

4. **技术栈**：Python FastAPI vs Node Express？→ 暂定不锁定，按实现者顺手。

5. **编辑器内核采用 Milkdown/ProseMirror 还是 Tiptap/ProseMirror？** → 暂定实现前做本仓库全量 Markdown 无损往返小样，选择差异最小的一种；产品要求不依赖具体内核。

6. **wiki/ 是否保留删除能力（F14）？** → 暂定保留，删除需二次确认；在线编辑能力已由本轮明确进入范围。
